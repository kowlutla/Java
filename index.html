Start with the concept, then explain the trade-offs and examples.

Answer

The four pillars are encapsulation, abstraction, inheritance and polymorphism.

  • Encapsulation: Keep state and behavior together and control access to state, commonly using private fields and public methods.
  • Abstraction: Expose essential behavior while hiding implementation details, often through interfaces and abstract classes.
  • Inheritance: Reuse and specialize behavior through an extends relationship. Prefer composition when it models the relationship better.
  • Polymorphism: Code can work with a parent type or interface while the runtime object determines the overridden instance method implementation.
interface Payment {
    void pay(int amount);
}

class CardPayment implements Payment {
    public void pay(int amount) {
        System.out.println("Paid by card: " + amount);
    }
}

Payment payment = new CardPayment();
payment.pay(500); // runtime dispatch
Interview tip: explain each pillar with a small example from a system you have built, rather than only reciting definitions.

Answer

For reference types, == compares whether two references point to the same object. equals() compares logical equality when the class provides an appropriate override. The default implementation inherited from Object is identity-based.

String a = new String("java");
String b = new String("java");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true

For primitives, == compares primitive values. When overriding equals(), also override hashCode(): equal objects must return the same hash code, which is essential for hash-based collections.

Do not say equals always compares content. Its behavior is defined by the class implementation.

Answer

A String cannot be changed after it is created. Operations that appear to modify a string create another string instead.

Immutability provides several benefits:

  • String pool safety: Multiple references can safely share the same pooled string.
  • Thread safety: Immutable values can be shared without synchronization for state changes.
  • Stable hashing: A string used as a HashMap key cannot change its equality or hash because its content was modified.
  • Security and reliability: Values such as class names, paths and configuration keys cannot be altered through an existing reference.
String name = "Java";
name.concat(" SE");
System.out.println(name); // Java

name = name.concat(" SE");
System.out.println(name); // Java SE

Use StringBuilder for repeated string changes in a single thread. Use StringBuffer when its synchronized operations are specifically needed.

Answer

HashMap stores key-value entries in an array of buckets. It uses the key's hashCode() to help select a bucket, then uses equals() to identify the matching key among entries in that bucket.

  • A hash is spread and mapped to a bucket index.
  • Collisions are handled within the bucket. Modern Java implementations can use a linked structure and may treeify a sufficiently populated bucket when capacity conditions are met.
  • When the size crosses the threshold determined by capacity and load factor, the table resizes and entries are redistributed.
Map<String, Integer> scores = new HashMap<>();
scores.put("Java", 95);
scores.put("SQL", 90);

System.out.println(scores.get("Java")); // 95

Average get/put performance is expected O(1) with a good hash distribution; collisions and resizing affect actual cost. HashMap is not thread-safe and permits one null key and null values.

Important contract: keys should have stable equality and hash-code behavior while they are stored in a hash map.

Answer

ArrayList is backed by a resizable array. LinkedList is a doubly linked list and also implements Deque.

  • Random access: ArrayList is O(1); LinkedList is O(n) because it must traverse nodes.
  • Append: ArrayList append is amortized O(1); LinkedList insertion at an already-positioned end is O(1).
  • Insert/remove in the middle: ArrayList shifts elements (O(n)); LinkedList needs O(n) traversal to find the position, then O(1) relinking.
  • Memory and locality: ArrayList usually has lower per-element overhead and better cache locality. LinkedList stores node links as well as values.

For most general-purpose list use cases, prefer ArrayList. Choose LinkedList when its deque operations and access pattern make it a good fit; benchmark representative workloads.

Answer

An interface defines a contract that unrelated classes can implement. An abstract class is a common base class that can share state and implementation with its subclasses.

  • A class can implement multiple interfaces but extend only one class.
  • An interface can define abstract methods, default methods, static methods and private helper methods; its fields are implicitly public static final.
  • An abstract class can have constructors, instance fields, and both abstract and concrete methods with varied access modifiers.
interface Auditable {
    void audit();
}

abstract class BaseEntity {
    private final long id;
    protected BaseEntity(long id) { this.id = id; }
    public long getId() { return id; }
}

Use interfaces for capabilities/contracts and abstract classes when closely related types genuinely share state or lifecycle implementation.

Answer

Garbage collection is the JVM's automatic memory-management process. A collector identifies objects that are no longer reachable from GC roots and reclaims their heap memory.

  • GC roots include references such as active thread stacks, static references and certain JVM-internal references.
  • Many collectors use generational strategies because object lifetimes often vary, though collector design differs.
  • GC can introduce pauses or concurrent CPU work; the impact depends on the collector, heap, allocation rate and workload.

You cannot reliably force garbage collection. System.gc() is only a request/hint to the JVM; the JVM may ignore it. Setting a reference to null does not immediately free the object if other reachable references remain.

Interview tip: distinguish an object becoming eligible for collection from the collector actually reclaiming its memory.

Answer

Both participate in Java Memory Model visibility guarantees, but they solve different problems.

  • volatile: Reads and writes of a volatile variable have defined visibility and ordering effects. It does not make compound operations such as count++ atomic.
  • synchronized: Provides mutual exclusion for a monitor and establishes a happens-before relationship between unlock and a subsequent lock on the same monitor. It can protect compound state transitions.
private volatile boolean running = true;

public void stop() {
    running = false;
}

public void runLoop() {
    while (running) {
        // do work
    }
}

Use volatile for suitable independent state flags or publication patterns. Use synchronization, locks or atomic classes when multiple operations must behave atomically.

Answer

A process is an executing program with its own virtual address space and operating-system resources. A thread is an execution path within a process.

  • Threads in the same process share heap memory and process resources, but each thread has its own stack and execution state.
  • Processes generally have stronger memory isolation; communication between them typically needs explicit IPC mechanisms.
  • Threads are useful for concurrent tasks but shared mutable state requires coordination to avoid data races.

In Java, application work is commonly managed with Thread, executors and higher-level concurrency utilities such as CompletableFuture.

Answer

Checked exceptions are checked by the compiler. A method must catch them or declare them with throws. Unchecked exceptions are subclasses of RuntimeException (and Error); the compiler does not require them to be caught or declared.

// Checked exception
try {
    Files.readString(Path.of("notes.txt"));
} catch (IOException e) {
    // handle or translate the failure
}

// Unchecked exception
int value = Integer.parseInt("not-a-number");
// NumberFormatException

Checked exceptions can represent recoverable conditions callers are expected to handle. Unchecked exceptions often represent programming errors or failures that callers may not be able to recover from locally. Choose based on the API contract, not merely convenience.

Avoid catching a broad exception and silently ignoring it. Preserve useful context when translating exceptions, and do not use exceptions for normal control flow.
